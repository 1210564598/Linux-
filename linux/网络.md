### 2.数据链路层协议

> mac地址/物理地址/硬件地址/以太网地址：同一个意思
>
> ​	数据链路层是在物理层提供的服务基础上向网络层提供服务，其最基本的服务是将来自网络层的数据可靠的传输到相邻节点的目标网络层。该层的主要作用有：物理地址寻址，流量控制，数据成帧，数据的检错，校验等。
>
> ​	主要协议：以太网协议
>
> ​	基本数据单位：帧
>
> ​	重要设备：交换机 ，网桥
>
> ​	最大传输单元：MTU(Maximum Transmission Unit)，数据链路层的数据帧不是无限大的，数据帧长度小于MTU



**mac地址**

> **mac是数据链路层的核心**
>
> 00:0c:29:c3:0a:15 
>
> 前24位：厂商地址（00:0c:29）
>
> 每个设备都拥有一个唯一的MAC地址，公有48位，使用十六进制表示



**mac广播地址：FF-FF-FF-FF-FF-FF**

**以太网协议：是一种使用最广泛的局域网技术**



**以太网帧结构**

> 类型（2字节）：标识上层协议
>
> 目的地址（6字节）

**ip地址**

> ​	ip地址就是设备在网络中的身份证号，ip地址由4个字节组成，共32位，理论上大约有42亿个ip地址，这个数字看起来很庞大，其实，现在已经远远不够用了。
>
> ​	常常用点分十进制来表示ip地址，有四个字节，每个字节8位，可以表示0到255之间的整数。
>
> ​	ip地址由两部分组成，一部分为网络号，一部分为主机号
>
> ​	网络号：公共前缀部分，用来表示一个网络；
>
> ​	主机号：即剩余部分，用来表示该网络中的一个主机，主机号全为0，表示一个网络，主机号如果全为1，表示广播地址
>
> ​	ip地址分类：
>
> ​		不同的网络，规模有大有小，根据实际需要来确定网络号和主机号的大小
>
> ​			A类：第一位总是0，网络号一个字节，主机号是3个字节，一般分配给大型网络
>
> ​						网络号可变位数：7位
>
> ​						网络个数：2^7^=128
>
> ​						每个网络支持的主机数为：2^24^-2=16777214
>
> ​						地址范围：0.0.0.0 ~ 127.255.255.255
>
> ​			B类地址：10000000:0000:0000:0000
>
> ​						前两位总是10，网络号两个字节，主机号2个字节，一般分配给中型网络
>
> ​						网络号可变位数：14位
>
> ​						网络个数：2^14^=16384
>
> ​						每个网络支持的主机数为：2^16^-2=65534
>
> ​						地址范围：128.0.0.0 ~ 191.255.255.255
>
> ​			C类地址：前三位总是110，网络号三个字节，主机号一个字节，一般分配给小型网络
>
> ​						网络号可变位数：21位
>
> ​						网络个数：2^21^=2097152
>
> ​						每个网络支持的主机数为：2^8^-2=254
>
> ​						地址范围：192.0.0.0 ~ 223~255.255.255
>
> ​			D类地址：前4位1110，用于组播通信
>
> ​						地址范围：224.0.0.0 ~ 239.255.255.255
>
> ​			E类地址：前4位1111，保留使用

### 4.传输层协议

> ​	负责将上层数据分段并提供端到端的可靠的或不可靠的数据传输，此外，传输层还要处理差错控制和流量控制问题。
>
> ​	传输层的协议：TCP协议（可靠），UDP协议（不可靠）(User Datagram Protocol)
>
> ​	端口：用来标记不同的进程（服务），**端口是传输层的核心**



**TCP协议报文格式**

> 源端口（16位）：表示发送者的端口号
>
> 目的端口（16位）：表示接收者端口号
>
> 序号（32位）：负责对传输的数据字节进行编号，以保证传输的数据顺序一致
>
> 确认号（32位）：用来标识接收端确认收到的数据段。确认号是收到的数据序号+1，然后放送给对方，代表我要接受你的下一个数据序号开始的数据段。
>
> 包头长度
>
> 标记位flags，其中典型的有：
>
> ​	SYN：代表同步请求连接
>
> ​	ACK：代表确认
>
> ​	FIN：代表终止连接，表示数据传输完毕，可以断开连接了
>
> ​	PSH：表示推送，希望对方马上给我响应
>
> ​	RST：复位，当遇到严重错误时，就需要复位，释放连接
>
> ​	窗口：做流量控制
>
> ​	校验和：
>
> ​	紧急指针：



**TCP三次握手：**

> 因为TCP是一个可靠协议，再发送数据前，必须建立连接，TCP建立连接有三步，简称三次握手
>
> ​	第一次：客户端向服务器发出连接请求；(SYN)
>
> ​	第二次：服务器向客户端响应(ACK)，同时也向客户端发出连接请求；(SYN)
>
> ​	第三次：客户端向服务器响应(ACK)



**TCP四次挥手**

> 第一次：客户端向服务器发送断开连接请求（FIN）
>
> 第二次：服务器给客户端响应（ACK）
>
> 第三次：服务器给客户端发送断开连接请求（FIN）
>
> 第四次：客户端给服务器响应（ACK）



### **5.HTTP协议**

> HTTP(Hyper Text Transfer Protocol) 超文本传输协议，用于从万维网（WWW World Wide Web）服务器传输超文本到本地浏览器的传送协议。
>
> HTTP交互流程：客户端发起请求，服务器响应
>
> HTTP协议特点：
>
> ​	支持B/S模式
>
> ​	无连接，只在一发一收之间有连接，消息处理完，连接断开；
>
> ​	无状态，因为不需要保持连接，不用记录状态；
>
> ​	简单：一个请求报文，一个响应报文

### 6.网络抓包

> ​	抓包就是将网络中的数据包进行截获，编辑，重发，转存等。常常用来进行网络协议分析，网络故障排查，检查和维护网络安全。
>
> ​	常用的抓包工具：命令行工具tcpdump，和图形化抓包工具wireshark



**tcpdump**

> tcpdump是一个类unix 系统下的抓包工具，可以抓取所有网络接口上的数据包。
>
> 用法说明：
>
> ​	tcpdump [options] proto dir type
>
> ​		**options** :
>
> ​				-i：指定tcpdump需要监听的网络接口（网卡）ens33，可以使用any表示所有网络接口
>
> ​				-D：列出tcpdump可以监听的所有的网络接口
>
> ​				-c：指定要抓取包的数量
>
> ​				-n：不解析主机名，直接用ip地址显示
>
> ​				-nn：除了-n的作用，还把端口显示为数值，否则端口显示为服务名	
>
> ​				-s len：设置tcpdump的数据包抓取的长度，len为o的话，抓取整个数据包
>
> ​				-A：打印报文的ASCII文本
>
> ​				-X：会以16进制和ASCII文本两种形式同时显示
>
> ​				-v：输出时会产生详细信息
>
> ​				-vv：产生比-v更详细的输出
>
> ​				-vvv：产生比-vv更详细的输出 
>
> ​				-w：将抓包数据输出到文件中，而不是标准输出 -w + 文件名

> ​		**protol**：通过给定协议限定匹配的数据包类型
>

IPC



> ​	socket（套接字）本质上是一组用于编写网络通信的API，提供了一种统一的接口，使得应用程序可以通过网络通信。在不同的操作系统中，Socket的实现方式可能有所区别，但它们都遵循相同的规范和协议，可以实现跨平台的网络通信。
>
> ​	进程间通信的方式(IPC)有：管道、消息、共享内存、信号量，这些方式都可以在本机进程之间通信，如果是网络中的通信，就可以使用Socket通信。
>
> ​	Socket起源于Unix，而Unix的基本哲学之一就是“一切皆文件”，而Socket也是一种有特殊的文件，对Scoket进行操作的函数就是对其进行读写打开关闭等操作。
>
> ​	Socket就是一个外观模式，它把复杂的TCP/IP协议实现细节隐藏在Socket接口的后面，对用户来说，一组简单的接口就是全部。



**套接字描述符**

> 套接字描述符就是一个整数，和咱们熟悉的文件描述符0，1，2没有什么区别



**Socket编程常用函数：**

> ​	**socket函数：**
>
> ​			int socket (int protofamily，int type，int protocol)	返回socket fd
>
> ​					protofamily：协议族，最常用的就是AF_INET(IPV4)
>
> ​					type：指定socket类型，最常用的，SOCK_STREAM，SOCK_DGRAM
>
> ​					protocol：指定协议，最常用的有，IPPROTO_TCP，IPPROTO_UDP
>
> ​	**bind函数：**
>
> ​		bind函数把一个ip地址和端口号组合起来赋给socket
>
> ​			int bind(int sockfd，const struct sockaddr* addr，socklen_t addrlen)
>
> ​					sockfd：即socket文件描述符
>
> ​					addr：指向要绑定给sockfd的协议地址
>
> ​					addrlen：对应的是地址的长度
>
> ​	**listen函数**
>
> ​			int listen (int sockfd，int backlog)
>
> ​					sockfd：即socket文件描述符
>
> ​					backlog：socket可以排队的最大连接个数
>
> ​	**connect函数：**
>
> ​		客户端通过调用connect函数和服务器建立连接
>
> ​			int connect (int sockfd，const struct sockaddr* addr，socklen_t addrlen)
>
> ​					sockfd：即客户端的socket文件描述符
>
> ​					addr：服务器的socket地址
>
> ​					addrlen为地址的长度
>
> ​	**accept函数：**
>
> ​		服务器依次调用socket()，bind()，listen()之后，如果有客户端调用connect函数就向服务器发送了一个连接请求，服务器监听到这个请求后，就会调用accept函数接收请求，这样，双方连接就建立成功了。之后，就可以进行网络读写即I/O操作，类似于普通文件的读写操作。	
>
> ​			int accept(int sockfd, struct sockaddr* addr, socklen_t* addrlen)	
>
> ​					sockfd：套接字问价描述符
>
> ​					addr：这是一个结果参数，它存储的是客户端的地址，如果对客户端的地址不感兴趣，就可以把这个值设置为NULL
>
> ​					addrlen：上述地址的长度，如果addr设为NULL，那么addrlen也应该设置为NULL
>
> 注意：accept函数会阻塞进程，直到有一个客户端连接建立后返回，它返回的是一个新的可用的套接字，这个套接字是连接套接字。
>
> read函数，write相关函数
>
> 此时，客户端和服务端已经建立好连接，就可以进行网络I/O读写操作，此类函数有多种，例如：
>
> ​	read/write，recv/send，recvmsg/sendmsg，recvfrom/sendto
>
> ​	**close函数：**
>
> ​		在服务器和客服端建立连接后，会进行读写操作，完成读写操作后，就要关闭相应的socket文件描述符。
>
> ​			int close(int fd)

## 2.基础

### 网络通信模型（B/S 与 C/S）

| 知识点       | 核心内容                                                     | 易混淆点 / 关键细节                |
| :----------- | :----------------------------------------------------------- | :--------------------------------- |
| 网络通信模型 | 介绍 B/S、C/S 两种网络架构设计模式                           | B/S 基于浏览器；C/S 基于独立客户端 |
| B/S 架构     | 浏览器 - 服务器模式，通过浏览器访问服务器必须使用 HTTP/HTTPS 协议 | 只能走 HTTP/HTTPS，不能自定义协议  |
| B/S 优势     | 跨平台简单、开发成本低、客户端无需额外开发                   | 无需安装客户端，打开即用           |
| B/S 劣势     | 协议单一、无法加载大量本地数据                               | 本地缓存、复杂交互能力弱           |
| C/S 架构     | 客户端 - 服务器模式，需开发专用客户端通信协议可自定义        | 协议自由，不限于 HTTP              |
| C/S 优势     | 协议灵活、可缓存 / 加载大量本地数据                          | 适合游戏、复杂桌面软件             |
| C/S 劣势     | 研发成本高、需多平台适配、要处理多线程                       | 更新麻烦，维护成本高               |
| 开发技术栈   | B/S：HTML/CSS/JSC/S：常用 Qt 框架                            | Qt 支持一次编写多平台运行          |
| 协议标准     | HTTP 是应用层协议，HTTPS 是加密版本                          | HTTPS 更安全，数据加密传输         |
| 核心区别     | 有无独立客户端、协议是否固定、本地处理能力                   | B/S 轻量跨平台；C/S 高性能强交互   |

### 服务器相关知识点

| 知识点               | 核心内容                                                     | 考试重点 / 易混淆点                             |
| :------------------- | :----------------------------------------------------------- | :---------------------------------------------- |
| 服务器的硬件定义     | 服务器是一台配置较高的主机，如云服务商（阿里云、腾讯云）提供的远程主机 | 硬件与普通主机的区别：配置高低、稳定性要求      |
| 服务器的软件定义     | 主机上运行能处理网络协议的应用程序（如 Nginx），具备解析网络协议的能力 | 软件服务器本质 = 进程 + 协议处理能力            |
| 服务器开发的核心任务 | 基于现有服务器框架（如 Nginx）开发业务逻辑，而非重复造轮子   | 与运维区别：开发侧重业务逻辑，运维侧重环境维护  |
| 服务器应用场景示例   | 1. 游戏后台（斗地主规则判定）2. 网盘系统（文件存储 + 用户数据库） | 网盘文件存在磁盘，数据库只存用户 - 文件映射关系 |
| 分布式文件系统       | 通过框架（如 FDFS）将多台主机整合为整体，解决单机存储瓶颈    | 分布式 vs 单机：性能、容量、成本、扩展性对比    |

### 公网/局域网IP分类

| 知识点       | 核心内容                                                    | 易混淆点                                                |

### OSI & TCP/IP 模型知识点

| TCP/IP 四层模型 | 网络接口层 → 网络层 → 传输层 → 应用层                        | 把 OSI 下两层合并、上三层合并  |

| 网络层协议      | IPv4 / IPv6                                                  | 地址长度、数量级区别           |
| 网络接口层      | 以太网帧协议                                                 | 编程基本不用关心，底层硬件相关 |

| 5    | 会话层     | 建立、管理、断开通信会话                  |

| 3    | 网络层     | IP 寻址、路由选择，跨网络传输             |
| 2    | 数据链路层 | 局域网内传输，用 MAC 地址寻址             |

### 网络协议

| 知识点       | 核心内容                                                     | 考试重点/易混淆点                                  |
| ------------ | ------------------------------------------------------------ | -------------------------------------------------- |
| 协议概念     | 双方必须遵守的约定，通过协商制定的共同认可文件（如网络协议） | 协议 ≠ 通用规则，需区分“约定”与“强制标准”          |
| 网络协议作用 | 通信两端按约定组织/解析数据，确保正常通信（如TCP/IP）        | 协议一致性：两端需使用相同协议（类比语言不通问题） |
| TCP协议结构  | 内存数据格式：源端口（2字节）、目的端口（2字节）、序号（4字节）、标志位（1字节）等 | 字段顺序与长度（如16位端口号 vs 32位序号）         |
| UDP协议特点  | 结构简单，无连接、不可靠传输（对比TCP的复杂性与可靠性）      | 适用场景差异：实时性（UDP） vs 可靠性（TCP）       |

### 数据网络发送与接收过程总结

| 过程             | 步骤          | 核心操作                                                     | 考试重点 / 易混淆点                        |
| :--------------- | :------------ | :----------------------------------------------------------- | :----------------------------------------- |
| 发送端（封装）   | 1. 应用层     | 准备待发送数据（如 HTTP 请求）                               | 数据初始形态，无任何头部                   |
|                  | 2. 传输层     | 添加 TCP/UDP 头（源端口、目的端口）                          | 端口信息用于定位接收方进程                 |
|                  | 3. 网络层     | 添加 IP 头（源 IP、目的 IP）                                 | IP 负责跨网络寻址，与 MAC 区分             |
|                  | 4. 网络接口层 | 添加 MAC 帧头（源 MAC、目的 MAC），转为比特流发送            | 最后一步封装，比特流通过硬件传输           |
| 接收端（解封装） | 1. 网络接口层 | 接收比特流，去掉 MAC 帧头，得到 IP 数据包                    | 解封装从最底层开始，反向操作               |
|                  | 2. 网络层     | 去掉 IP 头，得到 TCP/UDP 段                                  | 只剥离对应层级头部，不改动数据本身         |
|                  | 3. 传输层     | 去掉 TCP/UDP 头，得到应用数据                                | 端口匹配后，才会剥离头部传递上层           |
|                  | 4. 应用层     | 解析应用数据，展示给用户                                     | 最终步骤，还原发送端初始数据               |
| 核心规律         | -             | 发送：从上到下，层层加头部（封装）；接收：从下到上，层层剥头部（解封装） | 封装与解封装是反向操作，头部信息仅用于传输 |

# 套接字（Socket）通信 知识点

| 知识点          | 核心内容                                                     | 考试重点 / 易混淆点                       |
| :-------------- | :----------------------------------------------------------- | :---------------------------------------- |
| 套接字概念      | 是**IP + 端口**的封装，是系统提供的**网络通信接口**，用于进程间网络通信 | 套接字 ≠ 网络本身，而是网络通信的接口标准 |
| 通信模型        | 典型为 **C/S 模型**：客户端 + 服务器                         | 服务器被动等待，客户端主动连接            |
| 通信流程（TCP） | 服务器：创建 socket → 绑定 bind → 监听 listen → 接受连接 accept → 收发数据 → 关闭客户端：创建 socket → 连接 connect → 收发数据 → 关闭<br />服务器端流程（绑定地址→监听→接受连接）与客户端流程（发起连接→通信）差异 | **accept 会阻塞**，直到有客户端连接       |
| 核心函数        | socket()、bind()、listen()、accept()、connect()、send()、recv() | bind 绑定 IP 和端口；connect 发起连接     |
| TCP 特点        | 面向连接、可靠、流式传输                                     | 类似打电话，先拨号接通再聊天              |
| UDP 特点        | 无连接、不可靠、数据报传输                                   | 类似发短信，不用连接直接发                |
| 数据收发        | send /recv 用于传输数据；recv 会阻塞等待数据                 | 阻塞是高频考点：没数据就一直等            |
| 地址结构        | sockaddr_in 结构体：包含协议、IP、端口                       | IP 和端口必须转为**网络字节序**           |
| 字节序          | 网络统一使用**大端序**，主机多为小端序转换函数：htons、htonl、ntohs、ntohl | 不转字节序会导致端口 / IP 解              |

## 1、工作中 Socket 核心定位

- 用于**跨机器、跨进程网络通信**网络通讯api
- 常见场景：
  - 客户端 ↔ 服务端通信
  - 微服务之间内部调用
  - 网关、代理、心跳、日志上报
  - 设备通信（物联网、串口转网络、摄像头等）
- 工作中 **90% 用 TCP**，可靠、流式、常用

### 2、字节序

1.**主机序**x86 电脑：**小端序**

2.**网络序**统一规定：**大端序**

3.**转换函数**

- 端口（16 位）：`htons()`：主机 → 网络 /`ntohs()`：网络 → 主机
- IP（32 位）：`htonl()`：主机 → 网络  /`ntohl()`：`网络 → 主机

### 3.IP地址转换

```c++
在网络通信的时候，IP 和端口都需要使用大端模式 (网络字节序)
默认我们使用的 IP 和端口在本地是小端存储，在通信的时候需要转换
IP(ipv4) -> int -> 32bit
端口 (unsigned short) -> 16bit
h -> host -> 主机
n -> net -> 网络
s -> unsigned short
l -> unsigned int
头文件引用
#include <arpa/inet.h>
函数定义
// 主机字节序转换为网络字节序
// IP 是整形数，通常使用的 IP 地址是字符串 192.168.11.2
uint16_t htons (uint16_t hostshort); // 端口
uint32_t htonl (uint32_t hostlong); // IP 地址 (ipv4)
// 网络字节序转换为主机字节序
uint16_t ntohs(uint16_t netshort);
uint32_t ntohl(uint32_t netlong);
```

```c++

参数:

返回值:
成功: 1 (注：标准返回值为成功返回1，无效地址返回0，失败返回-1)

```

### 3. C++ 服务端最简完整代码（考试必背）

```c++
#include <iostream>
#include <cstring>
#include <unistd.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>

using namespace std;

int main() {
    // 1. 创建 socket
    int lfd = socket(AF_INET, SOCK_STREAM, 0);

    // 2. 绑定地址
    sockaddr_in addr{};
    addr.sin_family = AF_INET;
    addr.sin_port = htons(9999);
    addr.sin_addr.s_addr = htonl(INADDR_ANY);

    bind(lfd, (sockaddr*)&addr, sizeof(addr));

    // 3. 监听
    listen(lfd, 128);

    // 4. 接受连接
    int cfd = accept(lfd, nullptr, nullptr);
    cout << "客户端已连接" << endl;

    // 5. 收发数据
    char buf[1024] = {0};
    recv(cfd, buf, sizeof(buf), 0);
    cout << "收到：" << buf << endl;

    send(cfd, "hello from C++ server", 22, 0);

    // 6. 关闭
    close(cfd);
    close(lfd);

    return 0;
}
```

### 4. C++ 客户端最简代码

```c++
#include <iostream>
#include <cstring>
#include <unistd.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>

using namespace std;

int main() {
    // 1. 创建 socket
    int fd = socket(AF_INET, SOCK_STREAM, 0);

    // 2. 连接服务器
    sockaddr_in addr{};
    addr.sin_family = AF_INET;
    addr.sin_port = htons(9999);
    inet_pton(AF_INET, "127.0.0.1", &addr.sin_addr);

    connect(fd, (sockaddr*)&addr, sizeof(addr));

    // 3. 收发
    send(fd, "hello", 5, 0);

    char buf[1024] = {0};
    recv(fd, buf, sizeof(buf), 0);
    cout << "服务器回复：" << buf << endl;

    // 4. 关闭
    close(fd);

    return 0;
}
```

### 5. 一句话记忆

- **服务端**：socket → bind → listen → accept → recv/send → close
- **客户端**：socket → connect → send/recv → close
- **端口必须 htons，IP 必须网络字节序**
